# 개발 및 검증 계획

## 1. 진행 순서

| 단계 | 작업 | 완료 산출물/판정 |
|---|---|---|
| 0. 기술 검증 | Rust/Tauri·Windows 빌드 환경 확인, Windows API로 최소 MSI 생성, CAB·동적 레지스트리·날짜 실험 | 재현 명령, 시험 MSI, 결과 기록, 기술 선택 확정 |
| 1. 코어 모델 | 프로젝트 모델, 변수 파서·의존성, 입력 검증, .embproj XML 저장 | 예제 프로젝트 왕복 저장, 오류 위치 진단 |
| 2. 기본 빌드 | 파일 수집, 자체 MSI 테이블 생성, CAB 포함, 취소·로그 | 샘플 앱 설치/제거 성공 |
| 2-파일 확장 | 폴더 재귀 수집, 상대 경로·파일별 컴포넌트·안정적 ID | 구현 및 자동 검사 완료; multi-file-test.md 사용자 시험 대기 |
| 2a. 외부 CAB | 빌드 화면의 내장/외부 선택, 단일 외부 CAB 출력 | MSI+CAB 세트 설치·복구 및 누락 진단 |
| 2b. CAB 분할 | Data1.cab/Data2.cab 생성, 크기 설정, 대용량 경계 검증 | 실제 시험으로 지원 한도 확정; cab-packaging.md 참조 |
| 3. 레지스트리 | 형식·영역·변수 변환, 날짜·드라이브 계산, 유지 정책 | 상세 명세에 따른 설치 시험 통과 |
| 3a. 프로그램 실행 | 설치·제거 다중 항목, 인수·변수, 창 숨김, 순서·실패 처리 | 프로그램 실행 명세의 VM 시험 통과 |
| 4. UI 연결 | Tauri 기반 제품·파일·레지스트리·변수 편집, 오류 이동, 빌드 화면 | 코드 편집 없이 MSI 생성 |
| 5. 수명 주기 | 업그레이드, 복구, 롤백, 무인 설치 | 시험 행렬 통과 및 알려진 제한 문서화 |
| 6. 배포 준비 | 빌더 배포, 사용 안내, 도구 의존성 안내 | 새 개발 PC에서 재현 가능 |

첫 구현은 설치 화면을 포함한 파일 하나짜리 MSI 생성기로 진행한다. Rust CLI와 MSI UI 테이블을 먼저 작성하고 Tauri 화면은 이후 연결한다. 현재 시험 결과와 미완료 검증은 [첫 MSI 시험 안내](first-msi-test.md)에 기록한다. 일정은 기술 검증 후 산정한다.

## 2. 먼저 확인할 기술 위험

무료 배포 및 소스코드 공개 방침에 맞춰 프로젝트 라이선스를 선정하고, 빌드 엔진·확장·실행 도우미별 라이선스와 고지·소스 제공 의무를 기록한다. 특히 WiX를 사용하지 않는 방향을 유지하고, Tauri 자체 패키징에서 WiX가 자동 사용되지 않는지 확인한다. Windows API와 기타 의존성의 사용·배포 조건은 각각 검토한다.

1. 레지스트리 키·값 이름·데이터 각각에서 변수와 리터럴 기호가 정확히 전달되는가?
2. 대상 PC의 날짜를 고정 형식으로 계산하고 복구 때 보존할 수 있는가?
3. 무인 설치에서도 설치 경로 변경과 InstallDrive 계산이 올바른 순서로 실행되는가?
4. 컴포넌트 제거·유지 정책이 업그레이드와 롤백에 미치는 영향은 무엇인가?
5. x86/x64 패키지가 지정한 레지스트리 영역과 Program Files 폴더를 사용하는가?
6. 프로그램 실행의 창 숨김, 권한·세션, 인수 직렬화, 제거 시점, 업그레이드 조건이 일반/무인 설치에서 동일한 정책으로 동작하는가?

각 실험은 예상값, 실제값, 사용한 도구 버전, 설치 로그, 통과 여부를 기록한다. 구현 불가 또는 정책 변경이 필요한 경우 관련 명세와 결정 기록을 먼저 갱신한다.

## 3. 자동 검증

- 변수: 정상 참조, 순환·미정의 참조, 중괄호 이스케이프, 깊은 의존성, 대소문자.
- 위치 제약: 설치 경로의 자기 참조, 소스 경로의 설치 시점 변수, 잘못된 DWORD.
- 변환: MSI 특수 기호(`[`, `]`, `{`, `}`, `#`, `%`, `~`)가 의도한 문자열로 전달되는지 확인.
- 저장: .embproj XML 왕복, 상대 경로, 알 수 없는 스키마, 중단된 저장 시 원본 보존.
- 파일: 누락, 대상 충돌, 출력 폴더 재수집, 한글·공백·긴 경로 진단.
- 빌드: 도구 실패/취소/출력 권한 오류가 성공으로 표시되지 않는지 확인.
- 실행 항목: 목록 순서 및 저장 왕복, 파일 참조, 변수, 인수 직렬화, 잘못된 시간 제한·실패 정책 검증.

## 4. 실제 설치 시험 행렬

실제 레지스트리를 변경하는 시험은 스냅샷이 있는 전용 Windows VM에서 수행한다. 개발 PC에서 자동으로 설치하지 않는다.

| 시험 | 조건 | 기대 결과 |
|---|---|---|
| 신규 설치 | x64 Windows, x64 MSI | 파일/레지스트리/바로가기 생성 |
| 32비트 설치 | x64 Windows, x86 MSI | 32비트 영역 및 해당 Program Files 사용 |
| 경로 변경 | C: 기본값을 D: 경로로 변경 | InstallDir·InstallDrive 일치 |
| 대상 환경 | 빌드 PC와 다른 폴더 배치 | 대상 PC 경로 사용 |
| 날짜 | 다른 지역 형식, 자정 인접 실행 | yyyy-MM-dd, 트랜잭션 내 일관성 |
| 복구 | 다른 날짜에 복구 | InstallDate 보존, 누락 리소스 복원 |
| 유지보수 화면 | 설치된 MSI 재실행 | 복구·제거 두 선택지만 제공, 설치 구성/경로 변경 없음 |
| 업그레이드 | 1.0.0 → 1.1.0 | 새 버전과 설치일 적용, 기존 버전 잔여 제거 |
| 다운그레이드 | 1.1.0 → 1.0.0 | 명확한 차단 메시지 |
| GUID 관리 | 같은 UpgradeCode, 버전 증가, 새 ProductCode | 이전 제품 제거 및 앱 목록에 최신 버전 하나만 존재 |
| 동일 버전 충돌 | 같은 계열·버전, 다른 ProductCode | 중복 설치 차단 |
| 제거 | remove/keep 혼합 | 정책대로 처리, 관련 없는 값 보존 |
| 롤백 | 파일/레지스트리 처리 후 의도적 실패 | 이전 상태 복원 |
| 무인 설치 | /qn, 명령행 설치 경로 | UI 설치와 동등한 변수 결과 |
| 사용자 컨텍스트 | HKLM 및 HKCU, 권한 상승 | 쓰기 대상 사용자와 영역 일치 |
| 충돌 | 동적 키 결과 중복 | 쓰기 전 오류, 부분 변경 없음 |
| 프로그램 실행 | 설치·제거 각 3개, 서로 다른 인수·창 설정 | 지정 순서와 설정 준수 |
| 실행 실패 | 시작 실패/비정상 종료/시간 초과 | stop/continue 정책 및 로그 준수 |
| 실행 수명 주기 | 복구·업그레이드·취소·롤백 | 중복 실행 방지, 외부 변경의 롤백 한계 기록 |

시험 명령 및 레지스트리 조회 결과는 구현 후 검증 기록으로 추가한다. Windows 10/Server/ARM64 지원은 별도 검증 전 보장하지 않는다.
