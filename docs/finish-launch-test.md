## 설정

CLI의 `--launch-file`은 소스 폴더 내 상대 경로의 EXE를 지정한다. 빌드 입력에 포함된 파일만 선택할 수 있고 절대 경로, 상위 경로, EXE가 아닌 경로는 거부한다. 현재 단일 파일 입력은 hello.txt로 설치하므로 이 기능은 폴더 입력과 함께 사용한다.

인수는 `--launch-arg`를 반복해 한 인수씩 전달한다. 공백·빈 인수·따옴표·끝 역슬래시를 Windows CRT 명령행 규칙으로 직렬화하고 MSI 대괄호 속성 문법은 이스케이프한다. 현재 인수는 리터럴이며 `{InstallDir}` 같은 빌더 변수 치환은 후속 구현이다. 인수 해석 규칙이 독자적인 프로그램은 별도 호환성 시험이 필요하다. 초기 CustomAction.Target 길이는 인코딩 후 255 UTF-16 코드 단위로 제한한다.

## 동작

- 실행 설정이 있으면 완료 화면에 `설치한 프로그램 실행` 체크박스를 표시한다. 기본 해제다.
- 새 설치의 전체 UI, 실행 파일 컴포넌트가 로컬 설치되는 상태에서만 표시 및 실행한다.
- 체크 후 마침을 누르면 DoAction → 선택 속성 초기화 → EndDialog 순서로 처리한다.
- 무인 설치에는 완료 화면 이벤트가 없으므로 실행하지 않는다. 복구·제거·업그레이드 제거 중에는 표시/실행하지 않도록 조건을 둔다. 업그레이드 자체는 아직 미구현이다.
- CustomAction은 설치된 파일을 참조하는 Type 18에 비동기·대기 없음 옵션을 더한 210이다. 실행 시퀀스에는 등록하지 않으며 InstallFinalize 이후 완료 화면에서만 호출한다.
- 시작한 앱 종료를 기다리지 않는다. 앱의 실행 성공·종료 코드는 설치 성공과 별개이며 앱 시작 실패 때문에 이미 완료한 설치를 롤백하지 않는다.
- 실제 계정·권한은 설치 UI 실행 컨텍스트를 따른다. 이 방식만으로 반드시 비상승 일반 사용자로 실행된다고 보장하지 않는다.
- 숨김 실행, 작업 폴더 지정, 설치·제거 중 다중 명령은 이번 단위에 포함하지 않았다.

## 시험본

`dist/launch-demo/Setup.msi`에는 Rust로 만든 DemoLaunch.exe가 포함되어 있다. 시험 프로그램은 메시지 창에 실행 파일 경로와 전달받은 인수를 표시하며 파일을 쓰지 않는다. 소스는 examples/demo-launch.rs다. 실제 제품과 같은 제품 코드를 쓰는 시제품이므로 이전 시험 제품을 제거한 환경에서 설치한다.

```powershell
msiexec.exe /i "D:\sources\Express-MSI-Builder\dist\launch-demo\Setup.msi" /L*v "D:\sources\Express-MSI-Builder\dist\launch-demo\install.log"
```

1. 신규 설치 완료 후 체크박스가 기본 해제인지 확인한다.
2. 체크 후 마침을 눌러 실행 창과 인수 `first argument`, `[literal]`을 확인한다.
3. 별도 신규 설치에서 체크하지 않고 마치면 실행되지 않아야 한다.
4. 복구·제거 완료 화면에 실행 항목이 없고 앱도 실행되지 않아야 한다.
5. 무인 설치도 앱을 실행하지 않아야 한다. 약관 포함 패키지이므로 ACCEPTLICENSE=1은 별도로 필요하다.

## 검증 상태

테스트 8개와 Clippy 통과. 설치 파일 참조, EXE/상대 경로 검증, 인수 직렬화, 체크 기본값 해제, 완료 화면의 실행 조건·순서 및 실행 시퀀스 미등록을 검사했다. MSI 생성 및 제한된 Installer 세션 열기도 통과했다. 실제 설치 후 프로세스 실행·무인 설치·복구·제거의 비실행 확인은 사용자 시험 전이다.
