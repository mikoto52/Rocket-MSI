# 다중 파일·하위 폴더 단위

최신 사용자 검증(2026-10-18): 시험본에 대해 **통과** 보고를 받았다. 아래 구현 당시의 실제 설치·복구·제거 시험 대기 상태를 갱신한다. 개별 예외 시나리오와 ICE 검증까지 통과한 것으로 간주하지는 않는다.

2026-10-18 구현. `build`의 첫 인수에 폴더를 지정하면 모든 일반 파일을 재귀 수집해 소스 루트 기준 상대 경로로 설치한다. 내장/외부 CAB 모두 지원하며 CAB는 아직 하나다.

## 동작과 제약

- 폴더 입력은 파일 이름·하위 폴더를 보존한다. 단일 파일 입력은 기존 시험과의 호환을 위해 hello.txt로 설치한다.
- 정규화한 상대 경로 순으로 CAB와 File.Sequence를 작성한다. 같은 파일 이름이 다른 폴더에 있는 경우 별도 파일로 처리한다.
- 파일당 컴포넌트와 KeyPath를 생성한다. 파일/폴더 ID는 상대 경로의 SHA-256 기반이고, Component GUID는 제품 계열·x64·상대 경로 기반 UUID v8이다. 파일 추가 및 소스 루트 이동에 영향을 받지 않는다. 구현에는 Windows CNG를 사용한다.
- MSI 8.3 별칭을 생성하고 같은 폴더 내 별칭 충돌은 오류로 처리한다. 이름의 대소문자만 다른 대상 경로, 지원하지 않는 MSI 파일명도 거부한다.
- 심볼릭 링크·junction 등 reparse point는 따라가지 않고 오류로 처리한다. 소스 내부의 출력 폴더도 거부한다.
- 빈 폴더 자체는 설치하지 않으며 빈 소스는 거부한다. 첫 버전의 수집 깊이는 64, 파일 수는 32767 이하, 개별 파일 크기는 i32 FileSize 범위로 제한한다. 단일 CAB 생성의 크기 제약은 별도 적용되며 대용량 지원을 의미하지 않는다.
- 소스 복사 이후의 실제 크기를 FileSize에 기록한다. 실행 중 다른 프로그램이 쓰는 파일의 원자적 스냅샷은 보장하지 않는다.
- 파일 버전/해시 메타데이터, 제외 규칙, 사용자 제품/GUID 편집, XML 로더는 별도 후속 구현이다.

## 시험본

내장: `dist/multi-embedded/Setup.msi`

외부: `dist/multi-external/Setup.msi` + `Data1.cab`

예상 설치 경로:

```text
Express MSI Builder Demo/
  readme.txt
  config/settings.json
  docs/사용 안내.txt
  data/readme.txt
```

기존 시험 제품과 제품 코드·버전이 같다. 이전 제품을 먼저 제거한 시험 환경에서 시작하고, 외부 방식은 두 파일을 함께 둔다.

```powershell
msiexec.exe /i "D:\sources\Express-MSI-Builder\dist\multi-external\Setup.msi" /L*v "D:\sources\Express-MSI-Builder\dist\multi-external\install.log"
```

확인 순서: 모든 파일의 경로·이름·내용 확인 → 중첩 폴더 파일을 삭제하고 복구 → 사용자 지정 설치 경로에서도 복원 확인 → 제거 후 모든 설치 파일이 없어졌는지 확인. 빈 폴더 잔존 여부도 기록한다.

## 자동 검증

5개 테스트와 Clippy 통과. 다중 파일의 MSI 행/디렉터리 관계, CAB 실제 압축 해제 후 파일별 원본 대조, 다른 폴더의 동일 파일명, 한글 경로, 파일 추가 시 기존 ID/GUID 보존, 내장/외부 생성, 빈 폴더 및 소스 내부 출력 거부를 확인했다. 실제 설치·복구·제거 및 ICE 검증은 아직 미완료다.
