# 설치·제거 프로그램 실행 명세

설치 완료 화면에서 앱을 선택 실행하는 기능은 별도 [완료 후 실행 명세](finish-launch-test.md)로 분리했다. 설치·제거 **중** 실행 목록도 구현했으며 현재 범위와 XML은 [실행 목록 및 시험 키트](actions-test.md)를 기준으로 한다. 아래에는 후속 GUI·사용자 변수·업그레이드 등 초기 설계가 포함된다. 오류 정책은 사용자 확정에 따라 ignore(무시), notify(알림 후 계속), stop(중단) 세 가지를 사용한다.

## 1. 요청 및 설계 상태

사용자 확정 요구사항: 설치 중 실행과 제거 중 실행을 각각 여러 개 등록하며, 모든 항목에 실행 프로그램, 인수, 창 숨김 선택을 제공한다. 아래 실행 시점·기본값·오류 정책은 이를 구현하기 위한 초기 설계안이다.

## 2. 쉽게 사용하는 편집 화면

프로그램 실행 화면에 **설치할 때**와 **제거할 때** 목록을 구분한다. 각 목록에서 추가, 복제, 삭제, 위/아래 이동, 사용 여부 변경을 지원한다. 개수는 UI에서 단일 항목으로 제한하지 않는다.

기본 편집 항목:

- 이름: 실행 목적을 알아볼 수 있는 표시명
- 프로그램: 설치 파일 목록에서 선택하거나 대상 PC의 실행 파일 경로 입력
- 인수: 한 인수씩 추가·편집하는 목록, 변수 삽입 버튼 제공
- 창 숨김: 체크박스, 기본값 해제

고급 설정에 작업 폴더, 실패 시 처리, 제한 시간, 업그레이드 때 실행 여부를 배치한다. 실행 순서는 목록 순서대로 표시한다. 설치 파일에서 프로그램을 선택하면 경로를 다시 입력하지 않아도 된다. 인수 목록으로부터 계산한 명령행은 읽기 전용 미리보기로 제공한다. 빌더에서 미리보기를 여는 동작은 프로그램을 실행하지 않는다.

## 3. 실행 모델 초안

| 필드 | 의미 / 기본값 |
|---|---|
| id / name / enabled | 안정적인 ID, 표시명, 사용 여부(기본 true) |
| executable | installedFile(프로젝트 파일 참조) 또는 targetPath(대상 PC 절대 경로 템플릿) |
| arguments | 문자열 배열, 기본 빈 배열; 각 원소가 하나의 인수 |
| hideWindow | 창 숨김 요청, 기본 false |
| workingDirectory | 작업 폴더 템플릿; 미지정 시 실행 파일이 있는 폴더 |
| failurePolicy | stop(기본), ignore 또는 notify |
| timeoutSeconds | 양의 정수 또는 null(제한 없음, 초기 기본값) |
| runOnUpgrade | 기본 false; 설치/제거 각 목록별 항목에 설정 |

XML 프로젝트는 `Actions/Install/Action`과 `Actions/Uninstall/Action` 요소에 항목을 저장하고 문서 순서를 실행 순서로 사용한다. 인수는 `Arguments/Argument` 요소 목록으로 저장한다. EXE 직접 실행이 초기 지원 범위다. PATH 검색이나 파일 연결에 의존하지 않는다. 실행 파일 선택 및 외부 도구 사용이 서비스 등록 같은 별도 전용 기능의 제공을 의미하지는 않는다.

인수와 작업 폴더, targetPath에 기존 기본 변수 및 사용자 변수를 허용한다. 실행 파일 경로와 인수는 별도로 저장한다. 공백·한글·따옴표·빈 인수·끝의 역슬래시가 보존되도록 Windows 명령행 직렬화를 검증한다. 셸을 경유하지 않으므로 `&`, `|`, `>` 등을 셸 연산자로 해석하지 않는다. 특수한 인수 해석을 사용하는 프로그램의 호환성은 별도 시험한다.

## 4. 실행 시점과 수명 주기

| 상황 | 초기 정책 |
|---|---|
| 신규 설치 | 파일 배치와 레지스트리 기록 이후, 설치 트랜잭션 완료 이전에 설치 목록 실행 |
| 명시적 전체 제거 | 파일·레지스트리 삭제 이전에 제거 목록 실행 |
| 복구/동일 버전 재설치 | 기본적으로 두 목록 모두 실행하지 않음 |
| 메이저 업그레이드 | 기본 미실행; runOnUpgrade=true인 새 패키지 설치 항목과 이전 패키지 제거 항목만 각 단계에서 실행 |
| 롤백 | 일반 설치/제거 목록을 반대 동작으로 재사용하지 않음 |

이전 버전의 제거 항목은 이전 MSI에 저장된 설정을 따른다. 새 프로젝트에서 이전 패키지의 동작을 소급 변경할 수 없다. 업그레이드 중 이전 버전 제거 순서와 새 버전 실행 시점을 기술 검증에서 확정한다.

프로그램은 순차 실행하고 각 프로세스가 종료된 뒤 다음 항목으로 진행한다. 비동기 실행은 초기 범위에 포함하지 않는다. 실행 직전에 경로와 작업 폴더를 검증하고 제거 시에는 저장된 실제 설치 경로를 사용한다. 빌드 PC의 경로로 대체하지 않는다. 제거 시 InstallDate도 저장된 설치 상태에서 가져온다.

## 5. 창 표시 및 실행 컨텍스트

창 숨김은 콘솔 창을 만들지 않도록 하고 주 창 숨김을 요청하는 실행 옵션이다. 대상 프로그램이 자체 생성하는 대화상자·자식 창까지 강제로 숨긴다는 보장은 하지 않는다. 무인 실행이 필요하면 프로그램이 제공하는 silent 인수도 함께 설정하도록 도움말을 제공한다. MSI 자체의 UI 표시와 개별 프로그램의 창 숨김은 별개다.

창 숨김 해제는 정상 창 표시 요청이며, 상승 권한 설치·SYSTEM 계정·비대화형 세션에서는 화면 표시를 보장하지 않는다. 초기 실행 컨텍스트는 컴퓨터 전체 MSI의 상승 권한 실행 컨텍스트로 제안한다. 로그인 사용자의 바탕 화면에서 앱을 여는 별도 기능은 후속 검토다. 실제 계정, 세션, 권한, 환경 변수는 기술 검증으로 확인하고 UI 도움말에 명시한다.

## 6. 종료와 실패

기본 성공 종료 코드는 0이다. 그 외 종료 코드, 파일 누락, 시작 실패, 제한 시간 초과는 실패로 처리한다. 첫 버전에서 3010 등 특수 코드를 자동으로 성공이나 재부팅 요청으로 해석하지 않는다.

- stop: 다음 항목 실행을 중단하고 MSI 작업을 실패 처리하여 MSI 관리 리소스의 롤백을 요청한다.
- ignore: 오류를 로그에 남기고 다음 항목을 진행한다.
- notify: 오류를 알리고 다음 항목을 진행한다. 무인 UI에서는 창 없이 로그에 남긴다.
- 취소/시간 초과: 실행 중 프로세스와 자식 프로세스의 종료 범위를 검증한다. 이미 분리 실행된 자식이나 외부 서비스 작업의 취소를 보장하지 않는다.

외부 프로그램이 만든 변경은 MSI가 자동으로 되돌리지 못한다. stop도 그 변경의 원상복구를 의미하지 않는다. 실행 대상에는 재시도 가능한 동작을 권장하며 별도 보상 실행/롤백 프로그램 등록은 후속 검토한다. 다른 MSI 설치를 중첩 실행하는 용도는 초기 지원 범위에서 제외하고 부트스트래퍼 검토 대상으로 둔다.

로그는 항목 ID, 시작/종료, 소요 시간, 종료 코드, 실패 사유를 기록한다. 인수 원문과 표준 출력은 기본 로그에 저장하지 않는다. 명령행에 넘긴 비밀 정보의 은닉은 보장하지 않는다.

## 7. 구현과 검증

MSI 실행 시퀀스와 통합하며 UI 시퀀스만으로 실행하지 않는다. 시스템 변경 동작에는 deferred custom action 사용을 검토하고, 제한된 속성 접근을 고려해 필요한 값을 CustomActionData 등으로 전달한다. 창 숨김·인수 처리·작업 폴더·제한 시간을 일관되게 제공할 실행 도우미의 필요성을 검증한다. 설치된 EXE는 배치 이후 및 삭제 이전에 실행해야 한다.

전용 VM에서 다음을 통과해야 한다.

1. 설치 3개·제거 3개 항목의 순서와 독립된 인수/창 옵션, 사용하지 않는 항목 건너뛰기.
2. 공백·한글 경로, 빈 인수, 따옴표·역슬래시, 변수 치환이 대상 EXE에 정확히 전달됨.
3. 콘솔/GUI 각각의 창 표시·숨김 요청과 무인 MSI 실행, SYSTEM 실행의 실제 동작 기록.
4. 시작 실패·비정상 종료·시간 초과 시 stop/continue 및 로그 결과 확인.
5. 제거 프로그램 실행 시 설치 파일·레지스트리가 아직 존재하고 기존 InstallDir/InstallDate가 전달됨.
6. 복구 때 미실행, 업그레이드의 양쪽 패키지 조건, 중도 실패/취소 시 중복 실행 및 외부 부작용 확인.

## 공식 근거

- [Custom Action Type 18](https://learn.microsoft.com/en-us/windows/win32/msi/custom-action-type-18): 설치된 실행 파일의 호출 시점과 종료 코드.
- [Deferred Execution Custom Actions](https://learn.microsoft.com/en-us/windows/win32/msi/deferred-execution-custom-actions): 실행 시퀀스, 시스템 변경, 속성 접근 제약.
- [Custom Action Return Processing Options](https://learn.microsoft.com/en-us/windows/win32/msi/custom-action-return-processing-options): 동기 실행과 실패 처리.


## 2026-10-19 실행 시점 개선

현재 GUI의 대상 종류 선택은 제거하고 프로그램 경로와 실행 시점을 입력한다. XML은 targetPath를 쓰고 기존 installedFile은 호환한다. 프로그램 경로와 인수에는 변수 삽입 버튼이 있다.

| timing | UI 표시 | 실행 시퀀스 |
|---|---|---|
| beforeInstall | 설치 시작 전 | MSI 트랜잭션 초기화 후, 페이로드 변경 전 (1610부터, 표준 액션 1800 회피) |
| beforeFiles | 파일 복사 전 | RemoveFiles 이후 / InstallFiles 이전 (3600부터) |
| afterFiles | 파일 복사 후 | InstallFiles 이후 / CreateShortcuts 이전 (4100부터) |
| beforeFinish | 설치 완료 전 | 파일·바로가기·레지스트리 기록 후, 제품 등록/완료 전 (5600부터) |
| beforeRemove | 파일 삭제 전 | 기존 제거 시점 유지 (2000부터) |

각 항목은 setter/deferred/clear 세 행을 사용한다. 실제 실행은 시점별로 정렬하고 같은 시점에서는 목록 순서다. UI 화면 표시 전 사전 실행이 아니라 MSI 실행 트랜잭션 안에서 실행한다. 미지정 설치 시점은 afterFiles다. 과거의 레지스트리 이후 실행을 필요로 하는 프로젝트는 beforeFinish를 명시해야 한다. 복구·업그레이드 실행 제외와 실패 정책은 유지한다. 외부 프로그램 변경의 자동 롤백을 보장하지 않는다.

추가 경로 변수: InstallDestination, SystemDir(아키텍처별), SystemDrive=WindowsVolume, TempDir=TempFolder. WindowsVolume은 Directory 식별자로 직접 사용하지 않고 별도 EMB_SYSTEMDRIVE 디렉터리를 CostInitialize 전에 설정한다.

참고: [커스텀 액션 순서](https://learn.microsoft.com/en-us/windows/win32/msi/sequencing-custom-actions), [WindowsVolume](https://learn.microsoft.com/en-us/windows/win32/msi/windowsvolume), [TempFolder](https://learn.microsoft.com/en-us/windows/win32/msi/tempfolder), [Registry Root](https://learn.microsoft.com/en-us/windows/win32/msi/registry-table).
