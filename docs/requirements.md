# 제품 요구사항

## 1. 목적과 결정 상태

2026-10-18 명칭 결정: 개발은 **Express MSI Builder** 코드명으로 계속한다. 정식 이름 후보에 **InstallEmbly**, **InstallPackora**를 기록하며 확정·상표 조사 완료로 간주하지 않는다. 현재 표시명·기본 BrandingText·`.embproj` 확장자는 변경하지 않는다. 이전 문서의 공식 이름 표현은 정식 명칭 확정 전까지 현재 개발 명칭을 뜻한다.

설치 스크립트를 직접 작성하지 않고 파일, 제품 정보, 레지스트리를 설정하여 MSI를 생성한다.

| 상태 | 내용 |
|---|---|
| 사용자 확정 | 프로그램 이름: Express MSI Builder, 프로젝트 파일: XML 기반 .embproj |
| 사용자 확정 | Express MSI Builder 무료 배포 및 소스코드 공개 |
| 사용자 확정 | Rust + Tauri로 구현; 이전 WinForms 선택을 대체 |
| 사용자 확정 | 설치 후 유지보수 화면은 복구·제거 두 기능만 제공; 설치 구성 변경 기능은 제공하지 않음 |
| 사용자 요청 | Windows MSI 설치 빌더, 레지스트리 설정, 설치일자·설치 경로·Program Files·Windows 경로 변수 |
| 사용자 요청 | ProgramData, SystemDrive, InstallDrive, WindowsDrive 변수 |
| 사용자 요청 | 설치 중·제거 중 실행할 프로그램을 각각 여러 개 지정, 항목별 인수 전달 및 창 숨김 선택 |
| 초기 구현 제안 | 한글 Windows 데스크톱 UI, 프로젝트 저장·열기, 바로가기, 설치·제거·업그레이드 |
| 구현 방향 | WiX 없이 자체 MSI 생성, Windows CAB 기능 활용 |
| 검증 후 확정 | 프런트엔드 프레임워크, 도구 버전·라이선스·배포 방식, 설치일자 보존 구현 |

이 문서의 세부 정책은 초기 설계안이다. 사용자 요청과 충돌하면 사용자 요청을 우선한다.

배포 라이선스의 종류는 미정이다. 소스코드 공개를 곧바로 특정 라이선스 채택으로 간주하지 않는다. 빌드 엔진 선정 시 개발자뿐 아니라 배포받은 사용자가 MSI를 생성할 때 적용되는 비용과 약관도 검토한다. 사용자 전체에 대한 무조건적인 무상 사용 보장은 의존성 검토 전 선언하지 않는다.

## 2. 첫 버전 범위

| ID | 기능 | 요구사항 |
|---|---|---|
| FR-01 | 제품 정보 | 제품 이름, 제작사, 버전, 패키지 아키텍처 입력 |
| FR-02 | 파일 | 소스 폴더 선택, 하위 폴더 목록, 파일별 포함·제외, 주 실행 파일 지정 |
| FR-03 | 설치 위치 | 기본 경로 템플릿 설정, 설치 시 최종 경로 변경 |
| FR-04 | 바로가기 | 시작 메뉴 및 바탕 화면 바로가기 선택 |
| FR-05 | 레지스트리 | 항목 추가·수정·삭제, 루트·키·값 이름·형식·데이터·영역·제거 정책 설정 |
| FR-06 | 변수 | 기본 변수 선택, 사용자 변수 정의, 참조 검증 및 예시 미리보기 |
| FR-07 | 빌드 | 사전 검증, 진행 상태, 취소, 오류 및 로그, 성공 시 MSI 위치 표시 |
| FR-08 | 프로젝트 | .embproj XML 저장·열기, 스키마 버전, 상대 소스 경로 지원 |
| FR-09 | 설치 수명 주기 | 신규 설치, 제거, 복구, 상위 버전 업그레이드, 하위 버전 설치 차단 |
| FR-10 | 프로그램 실행 | 설치·제거별 여러 실행 항목, 프로그램·인수·창 숨김 설정, 순서 편집 및 저장 |
| FR-11 | 제품 식별자 | UpgradeCode·ProductCode 조회/수정, GUID 생성 버튼, 자동 관리 및 변경 영향 안내 |
| FR-12 | 이용약관 | TXT/RTF 표시, 명시적 동의 후 진행, 무인 설치 동의 정책; 상세 내용은 license-and-branding.md 참조 |
| FR-13 | 브랜딩 | 환영 제외 배너 화면 하단 버튼 왼쪽 BrandingText, 기본 Express MSI Builder, 사용자 문구 변경 |
| FR-14 | CAB 출력 방식 | 초기에는 MSI 내장, 후속으로 빌드 화면에서 MSI 포함/외부 CAB 선택 및 Data1.cab, Data2.cab 분할 설정 |

초기 패키지 대상은 x86/x64이며 한 MSI는 하나의 아키텍처를 대상으로 한다. 초기 설치 범위는 컴퓨터 전체(per-machine)로 제안한다. HKCU는 설치를 실행한 사용자에게 적용되므로 모든 사용자에게 자동 적용되는 것으로 표시하지 않는다.

첫 버전 이후 검토: 사용자별 설치, ARM64, 서비스 등록, 파일 연결, 환경 변수 변경, 선행 런타임 설치, 자동 서명, 패치(MSP), 다국어 설치 UI, CLI 및 CI 연동. 프로그램 실행은 첫 버전에 포함하며, 전용 스크립트 편집기와 셸 문법 실행은 후속 검토한다.

## 3. 화면 흐름

프로젝트 생성/열기 → 제품 정보 → 파일 및 설치 경로 → 바로가기 → 레지스트리 → 프로그램 실행 → 변수 → 검증 및 빌드.

프로젝트 편집 화면은 단계 사이를 자유롭게 이동할 수 있게 한다. 변수 선택 목록에는 설명, 자료형, 설치 시 평가 여부와 예시를 표시한다. 미리보기는 실제 대상 PC의 값이 아닌 예시임을 표시한다. 오류를 클릭하면 해당 입력 항목으로 이동한다.

생성 MSI의 유지보수 화면은 **복구**와 **제거**를 선택하고 진행하는 흐름으로 한다. 복구는 누락되거나 손상된 설치 리소스를 MSI 규칙에 따라 복원하며, 제거는 해당 제품의 설치 리소스를 제거한다. 설치 기능 선택 변경이나 설치 경로 변경은 유지보수 화면에 제공하지 않는다. 프로토타입은 복구·제거 버튼과 실행 연결까지 구현했으며 실제 복구 시험은 [유지보수 시험 안내](maintenance-test.md)를 따른다. 복구의 레지스트리·설치일자·외부 프로그램 실행 정책은 각 상세 명세를 따른다.

## 4. 입력과 오류 처리

- 필수 제품 정보 누락, 잘못된 버전, 소스 파일 누락, 같은 대상 경로의 충돌은 빌드를 차단한다.
- 알 수 없는 변수, 순환 참조, 잘못된 레지스트리 데이터와 중복 항목은 빌드를 차단한다.
- MSI 버전은 `major.minor.build`로 제한하고 각 범위는 0–255, 0–255, 0–65535로 검증한다. 네 번째 숫자를 조용히 버리지 않는다.
- 도구 미설치, 빌드 실패, 출력 경로 접근 실패는 원인과 복구 방법을 표시한다.
- 빌드 중 UI가 응답해야 하며 실패·취소한 출력물을 성공 결과로 표시하지 않는다.
- 레지스트리 값은 기본적으로 비밀 정보 저장 용도로 취급하지 않는다. 암호 입력 기능은 제공하지 않는다.

## 5. 완료 조건

1. 샘플 앱 폴더와 제품 정보를 저장하고 다시 열어 동일한 설정으로 MSI를 생성한다.
2. 빌드 PC와 다른 경로를 가진 시험 PC에서 변수 값이 시험 PC 기준으로 기록된다.
3. 설치 경로를 다른 드라이브로 바꾸면 InstallDir와 InstallDrive가 함께 반영된다.
4. 문자열·확장 문자열·DWORD·다중 문자열과 32/64비트 레지스트리를 검증한다.
5. 기본 삭제 항목은 제거되고 유지 항목은 남는다. 관련 없는 키/값은 삭제하지 않는다.
6. 복구 시 설치일자가 바뀌지 않으며 업그레이드와 롤백 결과가 명세와 일치한다.
7. 일반 UI 설치와 무인 설치(`/qn`)가 같은 변수 및 레지스트리 결과를 만든다.
8. 설치 및 제거에 각각 두 개 이상의 프로그램을 등록하고 저장·다시 열기 후 지정한 순서·인수·창 표시 설정으로 실행한다. 세부 완료 조건은 [프로그램 실행 명세](program-actions.md)를 따른다.
